# GMod Optimization & Security

Правила производительности и безопасности для GLua. Полное руководство с
примерами кода — в `references/optimization_and_security.md` (на русском):
читай нужный раздел при работе над соответствующей темой, не пересказывай
по памяти.

**Главный приём на клиенте — кэширование, и его чаще всего имитируют.**
Перед любой правкой рендер-хука читай `references/caching.md`: там
архитектура «источник изменения → кэш → кадр», готовые примеры, что НЕЛЬЗЯ
уносить из кадра, и признаки мнимого кэша.

**Точные сигнатуры API, реалмы, хуки, енумы** — это зона glua-скилла
(`/glua:glua`): не угадывай сигнатуры, сверяйся с его `references/`.

## Реалм-модель (минимум, который нужен всегда)

- `SERVER` / `CLIENT` — два раздельных Lua-состояния, память не общая.
  "Shared" — файл, загруженный в оба, не третье состояние.
- Рендер (`surface`, `render`, `cam`, `draw`, `vgui`) — только клиент.
  Спавн, урон, `util.AddNetworkString` — только сервер.
- Сервер решает, что попадёт клиенту: `AddCSLuaFile` + `include`.
- Никогда не доверяй данным от клиента: всё, что пришло через `net`,
  concommand или клиентский конвар — валидируется на сервере.

## Ядро правил производительности

**Частота вызова — главный множитель стоимости.** Прежде чем писать код,
определи, как часто он выполняется:

| Горячий путь | Частота |
|---|---|
| `HUDShouldDraw` | сотни раз/сек (5+ за кадр) — только lookup-таблица |
| `HUDPaint`, `Think` (клиент), `CalcView`, `CreateMove` | каждый кадр |
| `Pre/PostDraw*Renderables` | несколько раз за кадр (depth + skybox) — фильтруй `bDrawingDepth`/`bDrawingSkybox` первой строкой |
| `PrePlayerDraw`/`PostPlayerDraw` | × число видимых игроков за кадр |
| `Tick`, `ENT:Think` (сервер) | каждый тик (66/сек) |
| `SetupMove`, `Move` | на обработку движения игрока; prediction может повторять вызовы |

**Два главных запрета:** не обходи всех игроков, когда можно работать с
таблицей нужной группы; не выполняй никакую заменяемую математику или
обработку каждый кадр — считай на событии либо таймером и читай готовый кэш.

В горячем пути:

1. **Ноль аллокаций за кадр**: `Color()`, `Vector()`, `{}`, конкатенация
   строк, `string.format`, замыкания — всё это мусор для GC → микрофризы.
   Создавай один раз при загрузке файла, переиспользуй (`col.a = x`,
   `vec:SetUnpacked(...)`).
2. **Кэшируй за пределами выполнения**: локализуй глобальные функции в
   upvalue (`local floor = math.floor`), кэшируй `LocalPlayer()` лениво,
   `ScrW()/ScrH()` — с пересчётом по `OnScreenSizeChanged`,
   `surface.GetTextSize` — пока текст не изменился, `Material()` и
   `surface.CreateFont` — никогда внутри рендер-хуков.
3. **Запрещена любая заменяемая покадровая работа**: математика, обходы,
   агрегация, поиск цели, форматирование и проверки состояния уходят на
   событие изменения; если события нет — в таймер, например 0.1с.
   **Собирай данные таймером, рисуй хуком**: таймер (0.1–0.5с) складывает
   значения в плоские локалы, `HUDPaint` только читает их и рисует — даже
   `CurTime()` уходит из кадра. Считать надо **на источнике изменения**:
   разрешение → `OnScreenSizeChanged`, настройка → `cvars.AddChangeCallback`,
   пакет → `net.Receive`, видимость → `PostPlayerDraw`/`RenderOverride`.
   В кадре остаётся необходимая анимация (`Lerp`/`Approach`), актуальная
   проекция/transform движущихся объектов, ввод и `Draw*`.
   Запомнить результат, оставив вычисление в кадре, — это не кэш
   (`references/caching.md`).
4. **hook.Add → hook.Remove**: хук существует только пока нужен. Для хуков,
   привязанных к энтити/панели, передавай сам объект вторым аргументом —
   хук автоудалится при невалидности (объект придёт первым аргументом в
   callback). Уникальные имена хуков в цикле = утечка.
5. **Таймеры**: один глобальный таймер на всех игроков вместо N; удаляй
   по-игроковые таймеры в `PlayerDisconnected`; 50+ активных таймеров —
   повод для рефакторинга.
6. **Сеть**: `net.WriteUInt` с минимальными битами, никогда `WriteTable`;
   отправляй при изменении с тротлингом, не каждый тик; `net.Send(близким)`
   вместо `Broadcast`; NetworkVar (DTVar) > NW2 > NW.
7. **Максимально избегай обхода всех игроков**: `player.Iterator()` не
   исправляет лишний полный проход. Для группы поддерживай таблицу
   `[ply] = true` на событиях вступления/выхода и обходи только её;
   очищай при снятии статуса, смерти/смене роли по правилам фичи и дисконнекте.
   Не пересобирай группу полным обходом в каждом таймере.
8. **Разовое изменение — разовый пересчёт**: эффекты, производные значения
   и параметры обновляй на событии изменения их источника, не в частом хуке.
   **`SetupMove` считай самым нагружаемым хуком при выборе места для логики**:
   он выполняется для движения каждого игрока, prediction повторяет вызовы.
   Оставляй там только обязательную обработку движения с готовыми данными;
   обходы, агрегацию, поиск и пересчёт состояния выноси, сохраняя prediction.
   Взаимодействие запускай на `KeyPress`/`PlayerUse`, не постоянным поиском.
9. **HUD включается событием**: данные отправляй затронутому клиенту при
   активации/изменении/снятии эффекта; хук рисования включай пока есть контент.
   Таймер 0.5с + обход всех + сравнение сигнатур — лишний polling даже
   при подавлении одинаковых пакетов. Обратный отсчёт ведёт клиент.
10. **Контент и проверки**: уже опубликованные шрифты/модели/материалы
    доставляй Workshop, не дублируй `resource.AddFile`. Массовые самопроверки
    (тесты), генераторы и переборы решений создавай в отдельной папке
    `addons/dev_tests`, не в папке проверяемого аддона и не в shared/autorun.
11. **Сначала расставь пункты по стоимости, потом правь.** Порядок цены за
    кадр: арифметика (наносекунды) < строка, аллокация < `surface.GetTextSize`,
    `draw.SimpleText`/`DrawText` с выравниванием, вызов движка < отрисовка RNDX
    (настройка шейдера и проход по всему прямоугольнику) < пересборка VGUI,
    SQL, полный обход игроков. Иди сверху вниз и не полируй арифметику, пока
    в кадре остаются десятки отрисовок статичного содержимого: это мнимый кэш
    (`references/caching.md`, разделы 0 и 6).
12. **Списки VGUI пересобирай только при смене содержимого.** Ответ сервера
    с тем же составом (сравни подпись `sid..nick`) строки не трогает. Изменение,
    пока экран скрыт, ставит флаг; пересборка — в `Think` экрана, когда он стал
    текущим (скрытая панель `Think` не получает, проверка бесплатна). Поиск
    прячет неподходящие строки, а не пересоздаёт их с `AvatarImage`.
13. **Сетевой обработчик сразу выходит, если ничего не изменилось.**
    Переключатель (микрофон, громкая связь, настройка), повтор того же
    состояния или отказ от несуществующего — `return` до любого пересчёта,
    записи в базу и рассылки. Повтор `true` → `true` не должен перестраивать
    голос всем звонкам и слать ростер восьмерым.
14. **База — пачками.** Частые дешёвые изменения (питомец, настройки, счёт)
    помечают запись флагом «изменён», таймер раз в 30–60 с пишет все флаги
    в одной `sql.Begin()`/`sql.Commit()`, плюс запись в `PlayerDisconnected`
    и `ShutDown`. Сразу пишется только действие, где списаны деньги, предметы
    или кредиты, и только если оно не отклонено. Предел — потеря последней
    минуты при падении сервера: помечай его комментарием `ponytail:`.
    Данные, которые сервер и так держит (ники онлайн-игроков, свой счёт
    недели), читай из памяти, а не из базы.

При работе с группами игроков, баффами, взаимодействиями, HUD-синхронизацией
или доставкой контента читай `references/event_driven.md`: там разбор
исправлений, границы применимости и проверка стоимости вложенных циклов.

## 2D-интерфейс: RNDX по умолчанию

Скруглённые прямоугольники, круги, контуры, дуги, размытие и тени рисуй
библиотекой RNDX — <https://github.com/wrefgtzweve/rndx>, а не
`draw.RoundedBox`, полигонами или своими шейдерами. Подключение: файл
`rndx.lua` с лицензией кладётся в аддон (`lua/<addon>/modules/rndx.lua`),
сервер делает `AddCSLuaFile`, клиент — `MyAddon.RNDX = include(...)`.
Шейдеры библиотека монтирует сама из встроенного GMA.

```lua
RNDX.Rect(x, y, w, h):Rad(12):Color(col):Draw()          -- залитый
RNDX.Rect(x, y, w, h):Rad(12):Color(col):Outline(1):Draw() -- контур
RNDX.Rect(x, y, w, h):Radii(tl, tr, bl, br):Texture(tex):Draw()
RNDX.Circle(cx, cy, r):Color(col):Outline(4):Angles(270, 270 + 360 * frac):Draw() -- дуга
```

- Builder без аллокаций: `RNDX.Rect` возвращает один общий объект. Его
  нельзя хранить между вызовами, цепочка всегда заканчивается `:Draw()`.
  Старые `RNDX.Draw*` помечены deprecated.
- **Текстура — один раз.** `:Material(mat)` на каждом вызове делает
  `mat:GetTexture("$basetexture")`. ITexture бери один раз при смене
  картинки (обои, миниатюра, RT превью) и передавай `:Texture(tex)`. При
  ленивой загрузке храни `false` для «текстуры нет», чтобы не искать её
  заново каждый кадр.
- Каждый `:Draw()` — настройка десятка параметров шейдера и проход по всему
  прямоугольнику: считай его дорогой операцией. Полоски в 1–3 px рисуй
  `surface.DrawRect` (скругления там не видно). Статичный композит из многих
  `:Draw()` уходит в render target (`references/caching.md`, раздел 6).
- `:Blur()` копирует экран в текстуру на каждом вызове, `:Shadow()` и
  `:Clip(pnl)` выключают обрезку VGUI: в кадре — только там, где без них нельзя.

## Ядро правил безопасности

Каждый `net.Receive` — вход для атакующего. Минимум: `IsValid(ply)`,
типы/диапазоны значений, права, дистанция, rate limit, лимит длины строк
и размера таблиц. Полный чеклист и готовый rate limiter — в разделах 4–5
руководства. SQL — только через `sql.SQLStr`; пути файлов — санитизация;
`RunString`/`CompileString`/`http.Fetch` в чужих аддонах — маркеры бэкдора.

## Регрессионные тесты — GLuaTest

При добавлении или изменении нетривиальной GLua-логики оставляй минимальный
тест, совместимый с [GLuaTest](https://github.com/CFC-Servers/GLuaTest).
При исправлении бага тест должен воспроизводить исходную ошибку и проверять
результат вызова реального кода аддона, а не копию его реализации.

- Файлы размещай в `addons/dev_tests/lua/tests/<addon_name>/`, отдельно от проверяемого аддона,
  не в `autorun` и не внутри аддона GLuaTest. Файл возвращает таблицу
  `return { groupName = "...", cases = { { name = "...", func = function(state) ... end } } }`.
  Проверки внутри `func` выполняй через `expect(actual).to.equal(expected)`
  и другие поддерживаемые expectations; точный API сверяй с установленным
  `gluatest/README.md`, `lua/gluatest/types.lua` и примерами `lua/tests/gluatest/`.
- Приоритет: валидация входов, права, деньги/инвентарь, лимиты и граничные
  значения. Не добавляй тесты на тривиальную отрисовку или совпадение текста исходника.
- Серверный case используется по умолчанию; клиентский помечай `clientside = true`.
  Для запуска одного case в обоих realms используй `shared = true` и
  `clientside = true`, чтобы загрузчик также отправил файл клиенту.
  В установленном GLuaTest клиентская/shared поддержка помечена как неполная;
  проверяй такие cases на реальном клиенте, не считай серверный прогон их проверкой.
  Верхний уровень файла должен загружаться в обоих realms: обращения к
  realm-specific API выполняй внутри подходящих cases или callbacks.
- Подменяй только необходимые внешние зависимости через `stub`; не имитируй
  весь движок. Для сущностей, сети и сохранения используй интеграционные
  проверки в реальном GMod с изолированными тестовыми данными.
- Используй `beforeEach`/`afterEach` и `cleanup` для очистки сущностей,
  таймеров, хуков и восстановления изменённого состояния, включая ошибку теста.
  Для асинхронного case укажи `async = true`, конечный `timeout` и вызови `done()`.
- На сервере разработки запуск: `gluatest_server_enable 1`, затем
  `gluatest_run_tests` в серверной консоли. Клиентские тесты требуют клиента
  и `gluatest_client_enable 1` на сервере до загрузки карты/раздачи файлов;
  перезагрузи карту и подключи клиент после включения этой настройки.
  GLuaTest также запускает тесты при загрузке карты; не запускай изменяющие
  состояние тесты на рабочем сервере с реальными данными игроков.
- Сообщай фактический результат запуска и realm. Если GMod/клиент недоступен,
  сохрани тест и явно укажи, что выполнение не проверено. Unit-тесты не
  заменяют визуальную проверку DHTML/HUD и замеры FPS/времени кадра.
