# Кэширование в GLua: главный приём

Отдельный файл, потому что это самое важное правило производительности на
клиенте, и его чаще всего имитируют вместо того, чтобы применять.

Разделы 1.2 и 1.8 основного руководства описывают частности (локализация
функций, переиспользование объектов, `LocalPlayer()`). Здесь — архитектура,
которая их связывает.

---

## Правило

> Кадр не считает. Кадр рисует готовое.
>
> Всё, что меняется реже кадра, вычисляется **на событии, которое его
> меняет**, и складывается в переменную. Рендер-хук только читает.

Кэш — это не «запомнить строку». Кэш — это **перенос самой работы** из кадра
на источник изменения. Если работа осталась в кадре, а запомнили её результат,
кэша нет.

**Любая заменяемая математика и обработка каждый кадр запрещена**, даже
если формула короткая. Сначала событие изменения, при отсутствии события —
таймер, например 0.1с; хук читает готовое. Это не отменяет необходимую
покадровую анимацию, проекцию и ввод (раздел 4).

### Куда уходит счёт

| Что меняется | Источник изменения | Где считать |
|---|---|---|
| геометрия, шрифты, масштаб | смена разрешения | `OnScreenSizeChanged` |
| настройки | правка ConVar | `cvars.AddChangeCallback` |
| состояние игрока, мира, цели | событие изменения; при его отсутствии — время | событие или активный `timer.Create` 0.1–0.5 с |
| данные от сервера | приход пакета | `net.Receive` |
| видимость объекта | решение движка | `PostPlayerDraw` / `RenderOverride` |
| анимация, наведение мыши | кадр | **остаётся в кадре** |

## 1. Эталон: таймер наполняет, кадр рисует

Плоские локалы, один именованный таймер, в хуке ни одного вызова движка.

```lua
local hp, armor, job, money, arrested, lockdownText

hook.Add("InitPostEntity", "MyHUD_Cache", function()
    timer.Create("MyHUD_Cache", 0.4, 0, function()
        local ply = LocalPlayer()
        if not IsValid(ply) then return end

        hp       = ply:Health()
        armor    = ply:Armor()
        job      = ply:getDarkRPVar("job")
        money    = ply:getDarkRPVar("money")
        arrested = ply:isArrested()
    end)
end)

hook.Add("HUDPaint", "MyHUD", function()
    draw_SimpleText(hp .. "%", "MyFont", 80, scrH - 32, col_white, TEXT_ALIGN_CENTER)
    -- ...
end)
```

Почему плоские локалы, а не таблица состояния: чтение upvalue дешевле поиска
по таблице, а читают их в кадре. Таблица оправдана только когда состояний
много и они принадлежат объекту (по записи на энтить).

**Интервал.** 0.4–0.5 с хватает для всего, что игрок не ловит на глаз (деньги,
работа, броня, список игроков). 0.1 с нужен там, где на экране тикает секунда
или задержка заметна (обратный отсчёт, подсказка под прицелом). Реже 0.5 с
экран начинает «врать».

## 2. ConVar — не читать в кадре

`ConVar:GetFloat()` в кадре — вызов движка ради числа, которое меняют раз в
жизни. Значение забирается один раз, дальше его обновляет callback.

```lua
local settings = {}

for key, default in pairs({ x = "14", y = "-4", scale = "0.07" }) do
    local name = "myaddon_" .. key
    local cv = CreateClientConVar(name, default, false, false)

    settings[key] = cv:GetFloat()
    cvars.AddChangeCallback(name, function(_, _, new)
        settings[key] = tonumber(new) or 0
    end, "MyAddonSettings")
end
```

Тот же приём для строк, зависящих от бинда или настройки: собрать текст один
раз, пересобирать в callback'е, а не форматировать каждый кадр.

## 3. Видимость спрашивать у движка, а не считать

Свой фрустум всегда грубее движкового и ошибается в худшую сторону: пропавший
элемент игрок видит сразу. Движок уже решил, рисовать объект или нет, — надо
только узнать его решение.

**Игроки** — `PostPlayerDraw` зовётся только для отрисованных:

```lua
local drawable = {}

hook.Add("PostPlayerDraw", "Tags_Mark", function(ply)
    drawable[ply] = true
end)

hook.Add("PostDrawTranslucentRenderables", "Tags_Draw", function(depth, skybox)
    if depth or skybox then return end

    for _, ply in ipairs(cachedPlayers) do -- список тоже из таймера
        if drawable[ply] then
            drawable[ply] = false -- гасим сразу: следующий кадр поставит заново
            DrawTag(ply)
        end
    end
end)
```

**Произвольные энтити** — `RenderOverride` вызывается только при реальной
отрисовке:

```lua
local rendered = setmetatable({}, { __mode = "k" }) -- слабая: удалённые уходят сами

local function MarkRendered(ent)
    if ent.MyMarked then return end
    ent.MyMarked = true

    local previous = ent.RenderOverride -- чужой не отбираем
    ent.RenderOverride = function(self)
        if previous then previous(self) else self:DrawModel() end
        rendered[self] = true
    end
end
```

Это важно не только ради отрисовки: если тяжёлая функция на первом вызове
шлёт net-запрос на сервер (частый паттерн в аддонах одежды и никнеймов), то
без гейта клиент запрашивает данные за объекты, которых не видит.

## 4. Что из кадра НЕ уносится

- **Анимация**: `Lerp`, `math.Approach`, `math.sin`, затухания. На 10 Гц
  видно ступеньки. Правильная схема: цель считает таймер, кадр её догоняет.
- **Наведение мыши и клик**: на 10 Гц кнопка ощущается залипшей.
- **Непрерывно убывающая дуга/полоса** короткой длительности.

```lua
-- таймер: только цель
targetFrac = duration > 0 and math_Clamp((endTime - now) / duration, 0, 1) or 0

-- кадр: только догон, dt-корректный и независимый от FPS
shownFrac = Lerp(1 - math_exp(-FrameTime() * SPEED), shownFrac, targetFrac)
```

### Дожать и перестать считать

Хвост `Lerp` бесконечный: без дожатия значение вечно интерполируется ради
долей пикселя, и «установившегося» состояния не наступает никогда.

```lua
local function Settle(cur, target, move)
    if not cur then return target end   -- ещё не появлялся — сразу на место
    if cur == target then return target end

    cur = Lerp(move, cur, target)

    local diff = cur - target
    if diff < 0.5 and diff > -0.5 then return target end

    return cur
end
```

Дальше по `cur == target` можно брать заранее посчитанные числа вместо шести
интерполяций. Тот же приём применим к альфе: при `alpha == 1` умножения на
единицу не нужны, ветка дешевле.

## 5. Строки и замеры

Строку пересобирать только при смене значения, из которого она собрана.
Внутри таймера на 10 Гц отдельные метки-часовые уже не нужны — три коротких
конкатенации на тик дешевле лишнего состояния, которое надо сбрасывать руками.

```lua
-- в таймере
local sec = math_ceil(endTime - now)
if sec ~= lastSec then
    lastSec = sec
    timeText = sec .. " сек."
end
```

`surface.GetTextSize` — один из самых дорогих вызовов `surface`. Мерить при
смене строки или шрифта, а не в кадре. Помнить, что `draw.SimpleText` с
выравниванием меряет строку **внутри себя** на каждом вызове.

## 6. Render target — когда содержимое статично

Композит всего слоя в один `DrawTexturedRect` оправдан, если картинка живёт
секундами: карточка с текстом, рамка, виньетка. Флаг «пора перерисовать»
взводится только при реальном изменении, а не каждый тик.

```lua
if hudDirty then RebuildRT() end
surface_SetMaterial(hudMaterial)
render_OverrideBlend(true, BLEND_ONE, BLEND_ONE_MINUS_SRC_ALPHA, BLENDFUNC_ADD)
surface_DrawTexturedRect(0, 0, L.w, L.h)
render_OverrideBlend(false)
```

Элементы, которые ползут каждый кадр (заливка полосы), из RT **исключаются** и
рисуются поверх готовой текстуры — иначе RT пришлось бы перерисовывать каждый
кадр, и смысл теряется. См. раздел 1.3 основного руководства.

**Не применимо**, когда содержимое меняется покадрово по замыслу (убывающая
дуга таймера): перерисовка RT каждый кадр дороже прямой отрисовки.

## 7. Когда кэш — самообман

Признаки того, что кэширование имитируется:

- закэширована **строка**, а число под ней считается в кадре: `ceil`, деление,
  сравнение остались, сэкономлена одна конкатенация;
- закэширован **вход** (`ScrH()` в локале), а формула (`* scrH / 1080`,
  `math.Round`, `math.max`) осталась в кадре и зовётся оттуда десятки раз;
- закэширована арифметика на десяток операций, а рядом в том же кадре два
  полноэкранных `render.UpdateScreenEffectTexture` и `Material:Recompute`;
- метки-часовые «сменилась ли секунда» **внутри** таймера, который и так
  тикает 10 раз в секунду;
- посчитаны и сохранены числа, а дорогая часть (десятки `DrawRect`) осталась.

Проверка одна: **сколько операций ушло из кадра и сколько там осталось.** Если
ушли наносекунды, а остались миллисекунды — работа сделана не в том месте.

## 8. Анти-паттерны из реальных HUD

Встречаются в том же файле, где рядом всё сделано правильно:

```lua
-- ❌ hook.Add внутри net.Receive: хук перевешивается на каждое сообщение
--    и никогда не снимается, а внутри — textWrap и GetTextSize каждый кадр
net.Receive("AdminMessage", function()
    hook.Add("HUDPaint", "AdminMsg", function() ... end)
end)

-- ❌ трассировка в кадре ради подписи на двери
hook.Add("HUDPaint", "door", function()
    local ent = LocalPlayer():GetEyeTrace().Entity
end)

-- ❌ Color() и HSVToColor() в кадре при наличии готовой палитры рядом
draw.SimpleText(txt, font, x, y, Color(255, 255, 255, 255))

-- ❌ ScrW()/ScrH() в кадре, когда scrW/scrH уже лежат в локалах файла
```

## Чеклист для рендер-хука

1. Есть ли здесь вызов движка (`Health`, `GetNW*`, `getDarkRPVar`, `ConVar:Get*`,
   `ScrW`, `GetEyeTrace`, `player.GetAll`)? → в таймер.
2. Есть ли конкатенация, `string.format`, `Color()`, `Vector()`, `{}`? → в
   таймер или в загрузку файла.
3. Есть ли арифметика, результат которой одинаков между кадрами? → в
   `relayout`/таймер.
4. Осталась ли только интерполяция, мышь и `Draw*`? → готово.
5. Обращения к `math.*`, `surface.*`, `CFG.*` локализованы в upvalue? →
   раздел 1.8.1.
6. Хук вообще висит, когда рисовать нечего? → раздел 1.9.
